Сервис принимает на вход текст отзыва и возвращает один из трёх классов: `negative`, `neutral` или `positive`, а также confidence score.  
В проекте реализован полный цикл: EDA, обучение baseline-моделей, выбор финальной модели, сохранение sklearn Pipeline, FastAPI-сервис, Streamlit-интерфейс, CSV batch-анализ, тесты и Docker-контейнеризация.

## 2. Постановка задачи и контекст

### Предметная область и задача

Предметная область проекта — анализ пользовательской обратной связи.  
Такая задача может быть полезна интернет-магазинам, службам поддержки и аналитическим отделам, которым нужно быстро понимать общее настроение клиентов по отзывам.

Проект решает задачу многоклассовой классификации текста.  
Пользователь вводит текст отзыва, а сервис автоматически определяет его тональность.

Возможный сценарий использования:

1. Пользователь или внешняя система отправляет текст отзыва в API.
2. Сервис обрабатывает текст.
3. Модель определяет тональность отзыва.
4. API возвращает класс тональности и уверенность модели.

### Формулировка задачи в терминах ML

- **Входные данные:** текст пользовательского отзыва.
- **Выход модели:** класс тональности:
  - `negative`;
  - `neutral`;
  - `positive`.
- **Тип задачи:** supervised text classification.
- **Модельный подход:** TF-IDF-векторизация текста и классические ML-модели.
- **Основные требования:** сервис должен быстро отвечать на запрос, использовать реальную обученную модель, возвращать понятный JSON-ответ и поддерживать запуск через API.

Пример входа:

```json
{
  "text": "Качество отличное, товар понравился"
}
```

Пример выхода:

```json
{
  "sentiment": "positive",
  "confidence": 0.971962339335859
}
```

### Целевые метрики качества

Для оценки моделей использовались:

- `accuracy`;
- `precision_macro`;
- `recall_macro`;
- `macro-F1`.

Основной метрикой выбрана `macro-F1`, так как задача является многоклассовой, и важно учитывать качество классификации по всем трём классам, а не только общую долю правильных ответов.

## 4. Модели и подходы

### Baseline-модели

Для решения задачи были выбраны классические модели машинного обучения для текстовой классификации.

Эксперименты выполнены в ноутбуке:

```text
notebooks/baseline_models.ipynb
```

Использовались следующие модели:

1. `DummyClassifier`;
2. `MultinomialNB`;
3. `LogisticRegression`.

Для преобразования текста в признаки использовался `TfidfVectorizer`.

`DummyClassifier` использовался как нижняя граница качества.  
`MultinomialNB` был выбран как быстрый классический алгоритм для текстовой классификации.  
`LogisticRegression` была выбрана как более сильный baseline для разреженных TF-IDF-признаков.

### Финальная модель

Финальной моделью выбрана связка:

```text
TfidfVectorizer + LogisticRegression
```

Она показала лучшее качество среди протестированных baseline-моделей по `macro-F1`.

Финальная модель обучается в:

```text
src/train.py
```

Сохранённая модель находится в:

```text
artifacts/sentiment_model.joblib
```

Метаданные модели сохраняются в:

```text
artifacts/model_metadata.json
```

Нейросетевые модели и трансформеры в текущей версии проекта не использовались, так как цель проекта — реализовать стабильный BASIC/BASIC+ end-to-end ML-сервис на классическом ML-подходе.

## 5. Экспериментальный протокол и результаты

### Экспериментальный протокол

Для экспериментов использовался подготовленный датасет после очистки.

Разделение данных:

- train: 80%;
- test: 20%.

Разделение выполнялось с параметрами:

- `random_state = 42`;
- `stratify = y`.

Стратификация использовалась для сохранения распределения классов в обучающей и тестовой выборках.

Модели оценивались на тестовой выборке по следующим метрикам:

- `accuracy`;
- `precision_macro`;
- `recall_macro`;
- `f1_macro`.

### Сравнение моделей

| Модель | Описание | Accuracy | Macro-F1 | Комментарий |
|---|---|---:|---:|---|
| DummyClassifier | Заглушка, предсказывает самый частый класс | 0.3361 | 0.1677 | Нижняя граница качества |
| MultinomialNB | TF-IDF + Naive Bayes | 0.7254 | 0.7268 | Быстрая классическая модель |
| LogisticRegression | TF-IDF + Logistic Regression | 0.7481 | 0.7492 | Лучшая baseline-модель |

Также была построена confusion matrix для лучшей модели:

```text
reports/confusion_matrix.png
```

Метрики экспериментов сохранены в:

```text
reports/metrics.json
```

### Выбор финальной модели

Финальной моделью выбрана `LogisticRegression` с TF-IDF-признаками.

Причины выбора:

- лучшая `macro-F1` среди протестированных моделей;
- высокая скорость обучения и инференса;
- простота интеграции в API;
- возможность получать вероятности классов через `predict_proba`;
- интерпретируемость и устойчивость классического ML-подхода.

Итоговая модель сохранена как sklearn Pipeline:

```text
TfidfVectorizer + LogisticRegression
```

Это удобно, потому что сервису не нужно отдельно выполнять векторизацию текста: весь пайплайн загружается из одного файла `sentiment_model.joblib`.

## 6. Архитектура решения и сервис

### Архитектура пайплайна

Общая схема проекта:

```text
Датасет отзывов
        ↓
EDA и очистка
        ↓
Обучение моделей
        ↓
sklearn Pipeline
        ↓
src/predict.py
        ↓
FastAPI API + Streamlit UI + CSV batch-анализ
```

Основные файлы сервисной части:

| Файл | Назначение |
|---|---|
| `src/preprocessing.py` | очистка текста |
| `src/config.py` | пути и параметры проекта |
| `src/train.py` | обучение и сохранение модели |
| `src/predict.py` | загрузка модели и предсказание |
| `src/api.py` | FastAPI-приложение |
| `src/batch_analysis.py` | пакетный анализ отзывов из списка текстов и DataFrame |
| `src/streamlit_app.py` | пользовательский Streamlit-интерфейс |
| `docker-compose.yml` | альтернативный запуск FastAPI-сервиса через Docker Compose |
| `tests/test_api.py` | тесты API |
| `tests/test_predict.py` | тесты функции предсказания |
| `tests/test_batch_analysis.py` | тесты batch-анализа |

### API и endpoints

В проекте реализован FastAPI-сервис с двумя основными endpoint.

#### `GET /health`

Проверяет, что сервис запущен и модель доступна.

Пример ответа:

```json
{
  "status": "ok",
  "model_loaded": true
}
```

#### `POST /predict`

Принимает JSON с текстом отзыва.

Пример запроса:

```json
{
  "text": "Качество отличное, товар понравился"
}
```

Пример ответа:

```json
{
  "sentiment": "positive",
  "confidence": 0.971962339335859
}
```

Если пользователь передаёт пустой текст, сервис возвращает ошибку валидации.

### Пользовательский интерфейс Streamlit

Дополнительно реализован Streamlit-интерфейс в файле:

```text
src/streamlit_app.py
```

Интерфейс запускается командой:

```bash
streamlit run src/streamlit_app.py
```

В нём есть два режима:

- **Один отзыв** — пользователь вводит текст, модель возвращает `sentiment` и `confidence`.
- **CSV-анализ** — пользователь загружает CSV-файл, выбирает текстовую колонку и получает результат batch-анализа.

Результат CSV-анализа содержит поля:

- `text`;
- `sentiment`;
- `confidence`;
- `error`.

Также отображается bar chart распределения классов и доступно скачивание результата в CSV.

## 8. Ограничения и дальнейшая работа

### Ограничения

Текущая версия проекта имеет следующие ограничения:

- датасет относится к одной товарной категории: женская одежда и аксессуары;
- модель может хуже работать на отзывах из других доменов;
- короткие отзывы могут быть неоднозначными;
- используется классический ML-подход без трансформеров;
- нет авторизации;
- нет хранения истории запросов;
- нет полноценного Prometheus/Grafana-мониторинга.

### Дальнейшая работа

Возможные направления развития проекта:

- добавить определение темы отзыва: доставка, качество, цена, сервис, другое;
